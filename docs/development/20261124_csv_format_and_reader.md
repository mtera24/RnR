## 2. 開発目的

2027年2月の研究会に向けて、Touchを用いた書字運動の教示・再現システムを開発する。

ひらがな「あ」の書字運動を対象とし、書字中と画間の移動中を音によって区別できるようにする。

最終的には、Record時に記録した運動と音声をReplay時に同期して再現する。

今回の開発では、その基盤となる以下の処理を刷新した。

- CSVファイル仕様
- 内部データ構造
- Record処理
- CSV保存処理
- CSV読み込み処理
- CSV形式検査
- 単体試験機能

Replay中の音声同期そのものは、今回の開発範囲には含まれていない。

## 4. 開発前の状況と問題点

### 4.1 音声出力

開発開始時点では、以下の機能が実装済みであった。

- Touchボタン2の押下中に音を出力する。
- ボタン2の解放時に音を停止する。
- Windows waveOut APIを使用する。
- サンプリング周波数44.1kHz。
- 16bit、モノラル。
- 440Hzの正弦波。
- 1秒分の音声バッファ2個による二重バッファ方式。
- サーボコールバック内では音声APIを呼び出さない。

ただし、音声出力情報はCSVファイルに保存されておらず、Replay時に再現できなかった。

### 4.2 CSV形式

従来のRecord CSVは、以下の7項目で構成されていた。

- 時刻
- X座標
- Y座標
- Z座標
- ジンバル角度1
- ジンバル角度2
- ジンバル角度3

ボタン状態および音声出力情報は保存されていなかった。

また、Record用、RAW用、リサンプリング済みReplay用のCSV形式および読み込み処理が統一されていなかった。

### 4.3 固定長配列

従来の実装では、運動データの格納に固定長配列を使用していた。

以下の問題があった。

- 記録可能な点数が固定されている。
- 配列容量と有効データ件数の区別が不明確である。
- 読み込み処理によっては配列容量を超える可能性がある。
- リサンプリング時に有効データ件数を正しく扱っていない。

RAWデータ1884点からリサンプリング済みデータ10000点が生成される問題も確認されていた。

旧処理の調査では、実際のRAWデータ件数ではなく、配列容量を基準として処理していることが問題点として確認された。

この問題の解消は次回以降の開発課題とする。

## 5. CSV仕様の策定

### 5.1 仕様書

正式なCSV仕様書を以下に作成した。

`docs/specifications/rnr_csv_format_v1.md`

仕様バージョン：1.0

仕様の詳細については、上記ファイルを正本とする。

### 5.2 基本方針

- 運動情報と音声情報を同一時系列で管理する。
- Record、RAW、Replayで共通のCSV形式を使用する。
- 旧CSV形式との後方互換性は維持しない。
- 列番号ではなく列名によって各項目を識別する。
- 列順の変更を許容する。
- 将来の仕様拡張を考慮する。
- CSV形式の妥当性と実機再生の安全性を分離して検査する。
- 記録された時刻を保持する。
- 必要な場合に別途リサンプリングを行う。

### 5.3 メタデータ

必須メタデータ：

| キー | 値 |
|---|---|
| format | RnR |
| version | 1.0 |

省略可能なメタデータ：

| キー | 内容 |
|---|---|
| title | データの名称 |
| device | 使用デバイス |
| source | データの生成方法 |
| created_at | 作成日時 |
| nominal_interval_ms | 公称サンプリング間隔 |
| interpolation_audio_freq | 周波数の補間方式 |
| interpolation_audio_amplitude | 振幅の補間方式 |

未知のメタデータは、将来の拡張を考慮して無視する。

### 5.4 データ列

| 列名 | 単位 | 必須 |
|---|---|---|
| time_ms | ms | 必須 |
| x_mm | mm | 必須 |
| y_mm | mm | 必須 |
| z_mm | mm | 必須 |
| gimbal1_rad | rad | 任意 |
| gimbal2_rad | rad | 任意 |
| gimbal3_rad | rad | 任意 |
| buttons | ビットマスク | 任意 |
| audio_freq_hz | Hz | 任意 |
| audio_amplitude | 正規化値 | 任意 |

### 5.5 時刻の仕様

- 非負整数とする。
- 単位はmsとする。
- 最初の時刻は0msとする。
- 以降の時刻は厳密な単調増加とする。
- 時刻の重複を許容しない。
- 時刻の逆転を許容しない。
- サンプリング間隔は一定である必要はない。

### 5.6 ボタン状態

ボタン状態はビットマスクで表現する。

| 値 | 状態 |
|---:|---|
| 0 | 押下なし |
| 1 | ボタン1 |
| 2 | ボタン2 |
| 3 | ボタン1とボタン2 |

ボタン状態と音声出力情報は独立して管理する。

Replay時の音声出力は、ボタン状態ではなく音声出力情報に基づいて制御する方針とする。

### 5.7 音声出力情報

- 周波数は0以上とする。
- 振幅は0以上1以下とする。
- 振幅は正規化値とする。
- 周波数または振幅が0の場合は無音とする。
- 音声情報の列が省略された場合は0を使用する。

CSV仕様上の許容範囲と、現在の音声出力機能で実際に再現可能な範囲は区別する。

### 5.8 補間方式

| 項目 | 基本方針 |
|---|---|
| 位置 | 線形補間 |
| ジンバル角度 | 周期性を考慮して別途検討 |
| ボタン状態 | 直前値保持 |
| 音声周波数 | 直前値保持を既定とする |
| 音声振幅 | 直前値保持を既定とする |

音声情報については、メタデータによって `hold` または `linear` を指定できる仕様とした。

補間処理自体は今回未実装である。

## 6. 内部データ構造の刷新

### 6.1 MotionSample構造体

1サンプル分の運動情報と音声情報を管理する構造体を導入した。

```cpp
struct MotionSample
{
    uint64_t time_ms = 0;

    double position[3] = {};
    double gimbalAngles[3] = {};

    uint32_t buttons = 0;

    double audio_freq_hz = 0.0;
    double audio_amplitude = 0.0;
};
```

### 6.2 vectorによる管理

用途別に以下のvectorを導入した。

```cpp
static std::vector<MotionSample> recordedData;
static std::vector<MotionSample> rawData;
static std::vector<MotionSample> replayData;
```

| 変数 | 用途 |
|---|---|
| recordedData | Recordによって取得したデータ |
| rawData | CSVから読み込んだ元データ |
| replayData | Replay用に処理したデータ |

元データとReplay用データを分離することで、リサンプリングや安全性検査による処理結果を元データと区別する。

### 6.3 vectorの運用方針

- `size()` によって有効データ件数を取得する。
- `clear()` によって前回のデータを破棄する。
- `reserve()` によって必要なメモリを事前確保する。
- `push_back()` によってサンプルを追加する。
- サーボコールバック内では動的メモリ確保を行わない。
- Replay中はReplay用データを変更しない設計とする。

Recordのvector化は完了した。

RAWおよびReplayの旧固定長配列は、現時点では残っている。

## 7. Record処理の刷新

### 7.1 実装内容

`RecordDeviceState()` を改修した。

- Record開始時に `recordedData` を初期化する。
- 必要なメモリを事前確保する。
- 最初のサンプルの時刻を0msとする。
- 以降の時刻をRecord開始時刻からの経過時間として保存する。
- 位置、ジンバル角度、ボタン状態を保存する。
- ボタン2の状態に対応する音声出力情報を保存する。
- Record終了後にCSV Version 1.0形式で保存する。

### 7.2 記録点数の上限

暫定的なメモリ使用量制限として、以下を設定した。

```cpp
static constexpr size_t MAX_RECORD_SAMPLES = 10000;
```

サンプリング間隔の設定値は10msである。

したがって、記録可能時間は約100秒である。

この上限は固定長配列に起因するものではなく、現在の運用上の制限である。

### 7.3 メモリ確保失敗時の処理

Record開始前に `reserve()` を実行する。

`std::bad_alloc` が発生した場合は、エラーメッセージを表示してRecordを中止する。

メモリ確保失敗時の実際の動作試験は未実施である。

### 7.4 旧実装との比較

移行途中では、旧固定長配列とvectorの両方に記録する方式を採用した。

以下を比較した。

- 記録点数
- 時刻
- 位置
- ジンバル角度

588点および983点の記録試験において、比較対象の不一致が0であることを確認した。

比較完了後、旧Record用配列と一時的な比較処理を削除した。

### 7.5 廃止した旧Record用変数

- `rec_position`
- `rec_gimbalAngles`
- `rec_timeidx`
- `end_idx_record`
- `LEN_REC`
- Record用の旧サンプルカウンタ `t`

## 8. CSV保存処理

### 8.1 出力形式

Record終了時に以下のメタデータを出力する。

```text
# format=RnR
# version=1.0
# source=recorded
```

ヘッダー：

```text
time_ms,x_mm,y_mm,z_mm,gimbal1_rad,gimbal2_rad,gimbal3_rad,buttons,audio_freq_hz,audio_amplitude
```

データ行は `recordedData` の各要素から生成する。

### 8.2 数値の保存精度

実数値の出力には `%.17g` を使用する。

double型の値をCSVへ保存する際の精度低下を抑えることを目的とする。

### 8.3 保存先

従来どおり `record.csv` に保存する。

実験によって生成された `record.csv` は、今回のソースコード変更のコミット対象から除外した。

### 8.4 残課題

- `fclose()` の戻り値の確認。
- ファイル保存失敗時の処理改善。
- 保存先ファイル名の選択機能。
- 音声周波数・振幅の定数の共通化。
- 運動記録用と音声制御用のボタン状態取得処理の統一。

## 9. 共通CSV読み込み処理

### 9.1 基本関数

以下の共通関数を実装した。

```cpp
static bool readMotionCSV(const char* filename);
```

CSVファイルの読み込みと形式検査を担当する。

実機再生の安全性検査は担当しない。

### 9.2 補助関数

| 関数 | 役割 |
|---|---|
| trim() | 文字列前後の空白除去 |
| splitCSVLine() | CSV行の分割 |
| findCSVColumn() | 列名から列番号を取得 |
| parseCSVDouble() | 実数値の変換・検査 |
| parseCSVUInt64() | 非負整数の変換・検査 |
| splitCSVMetadata() | メタデータのキーと値の分離 |
| setCSVMetadata() | メタデータの格納 |
| validateCSVMetadata() | メタデータの妥当性検査 |
| parseCSVHeader() | ヘッダーの解析・検査 |
| parseCSVSample() | データ行の解析・検査 |
| validateCSVSampleTime() | 時刻の妥当性検査 |

現在のCSV分割処理は、引用符によって囲まれたフィールドには対応していない。

### 9.3 補助構造体

以下の構造体を導入した。

- `MotionCSVColumns`
- `MotionCSVMetadata`

`MotionCSVColumns` は、各項目に対応する列番号を保持する。

列番号が-1の場合は、その列が存在しないことを示す。

これにより、省略された項目と値が0の項目を区別できる。

`MotionCSVMetadata` は、CSVファイルのメタデータを保持する。

### 9.4 読み込み結果の保持

```cpp
static MotionCSVMetadata rawMetadata;
static MotionCSVColumns rawColumns;
static bool RawDataReady = false;
```

運動データ本体は `rawData` に格納する。

### 9.5 読み込み処理の流れ

1. 前回の読み込み結果を初期化する。
2. `RawDataReady` をfalseにする。
3. `ReplayReady` をfalseにする。
4. CSVファイルを開く。
5. メタデータを読み込む。
6. メタデータの妥当性を検査する。
7. ヘッダーを解析する。
8. 必須列の存在を確認する。
9. 各データ行を解析する。
10. 数値と時刻の妥当性を検査する。
11. 正常なサンプルを `rawData` に追加する。
12. ファイル読み込みの正常終了を確認する。
13. データが1点以上存在することを確認する。
14. `RawDataReady` をtrueにする。
15. `ReplayReady` をfalseに維持する。
16. 読み込み結果を返す。

### 9.6 実装済みの形式検査

- ファイルの存在
- 必須メタデータ
- ファイル形式
- 対応バージョン
- メタデータキーの重複
- 公称サンプリング間隔の値域
- 音声補間方式
- 必須列の存在
- 列名の重複
- 空の列名
- データ行の列数
- 数値変換の成否
- 数値の変換可能範囲
- NaNおよび無限大
- 時刻の非負整数性
- 開始時刻0ms
- 時刻の厳密な単調増加
- ボタン状態の値域
- 音声周波数の値域
- 音声振幅の値域
- データ行の存在
- ファイル読み込みの正常終了

上記は実装済みの検査項目である。

すべての項目について動作試験が完了しているわけではない。

### 9.7 異常発生時の処理

CSV読み込み途中で異常を検出した場合は、読み込み済みの運動データを破棄する。

- `RawDataReady = false`
- `ReplayReady = false`
- `rawData` は空
- 関数の戻り値はfalse

メモリ確保失敗についても `std::bad_alloc` による例外処理を実装した。

### 9.8 CSV形式検査と再生許可の分離

今回の開発における重要な設計方針である。

| 状態 | RawDataReady | ReplayReady |
|---|---|---|
| 読み込み前 | false | false |
| 読み込み失敗 | false | false |
| 読み込み成功 | true | false |
| 実機再生準備完了 | true | true |

最後の状態への遷移は、今後実装する。

CSV形式が正常であっても、安全に実機再生できるとは限らない。

なお、上記の状態管理は新しい共通CSV読み込み経路についてのものである。旧Replay経路には未改修の処理が残っている。

## 19. 開発上の知見

- 運動データは構造体単位で管理する。

- 異常系試験用データをリポジトリに保存する。
- 機能単位で差分レビュー、コミット、pushを実施する。

これらの方針は、今後のTouch版RnRの開発だけでなく、他の運動生成プログラムやロボットアームを用いたRnRへの展開にも活用できる。
