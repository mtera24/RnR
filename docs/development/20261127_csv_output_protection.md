# CSV保存処理のファイル保護機構の実装

## 1. 開発日

2026年11月27日

## 2. 開発目的

RnR CSV Version 1.0の共通保存処理について、既存ファイルの誤上書きおよび書き込み失敗によるデータ消失を防止する。

今後のRecord保存処理およびリサンプリング済みCSV保存処理の統合に向けて、安全なファイル保存基盤を整備する。

## 4. 設計方針

### 4.1 上書き制御

- デフォルトでは既存ファイルへの上書きを禁止する。
- 明示的に上書きが許可された場合のみ、既存ファイルを置換する。
- writeMotionCSV() の引数として bool overwrite = false を追加する。
- 将来的にはCLIオプション --overwrite に対応する。

### 4.2 ファイル名管理

RnR本体と外部ツールの責務を分離する。

RnR本体の責務：

- 運動データの取得。
- CSV形式の検査。
- 安全なファイル保存。
- 指定されたファイル名の使用。

外部ツールの責務：

- ファイル名の生成。
- 日時を含むファイル名の付与。
- 保存先ディレクトリの選択。
- ファイルの選択・名称変更。
- 上書き確認などの利用者インタフェース。

RnR本体では、自動的な日時付きファイル名の生成を行わない。

### 4.3 一時ファイルを経由した保存

正式ファイルに直接書き込まず、出力先と同じディレクトリに一時ファイルを生成する。

処理順序：

1. メタデータの検査。
2. 運動データの検査。
3. 一時ファイルの生成。
4. 一時ファイルへのCSV出力。
5. 書き込みおよびクローズ結果の検査。
6. 正式ファイルへの反映。

書き込みまたは反映に失敗した場合は、一時ファイルの削除を試みる。

## 5. 実装内容

### 5.1 writeMotionCSVContent()

既存のwriteMotionCSV()からCSV出力の実処理を分離した。

担当する処理：

- ファイルのオープン。
- メタデータの出力。
- CSVヘッダの出力。
- 運動データの出力。
- 書き込み結果の検査。
- ファイルクローズ結果の検査。

入力データの検査およびファイル保護は呼び出し元が担当する。

### 5.2 writeMotionCSV()

CSV保存処理全体を管理する関数として再構成した。

担当する処理：

- validateCSVMetadata()によるメタデータ検査。
- validateMotionData()による運動データ検査。
- 一時ファイルの生成。
- writeMotionCSVContent()の呼び出し。
- 正式ファイルへの反映。
- 上書き制御。
- 失敗時および例外発生時の後処理。

### 5.3 createCSVOutputTempFile()

出力先と同じディレクトリに一時ファイルを生成する関数を追加した。

使用するWindows API：

- GetFullPathNameA()
- GetTempFileNameA()

出力先の絶対パスからディレクトリ部分を取得し、そのディレクトリ内に一時ファイルを生成する。

### 5.4 removeCSVOutputTempFile()

一時ファイルの削除処理を共通化した。

DeleteFileA()の戻り値を検査し、削除に失敗した場合はファイル名とWindowsエラー番号を表示する。

### 5.5 正式ファイルへの反映

MoveFileExA()を使用する。

- overwrite == false：既存ファイルの置換を許可しない。
- overwrite == true：MOVEFILE_REPLACE_EXISTINGを指定する。

ファイルの存在を事前に確認するだけではなく、実際のファイル移動時に上書きの可否を制御する。

### 5.6 例外処理

writeMotionCSVContent()の呼び出しをtryブロックで囲んだ。

例外発生時はcatch (...)で捕捉し、一時ファイルの削除を試みた後、throw;によって例外を再送出する。

例外を握りつぶさず、後処理のみを担当する設計とした。

## 6. 単体試験

### 6.1 既存試験の修正

W01およびW02～W16の共通試験関数について、明示的に上書きを許可するよう変更した。

既存の試験用ファイルが存在することによって、本来の検査目的が損なわれることを防止する。

## 8. 既知の制約および未検証事項

### 8.1 ファイル保護

以下の障害を意図的に発生させる試験は未実施である。

- 一時ファイル生成失敗。
- 書き込み途中の障害。
- ファイルクローズ失敗。
- C++例外発生。
- 一時ファイル削除失敗。

一時ファイルが残存していないことを直接検査する試験も未実施である。

停電およびプロセスの強制終了に対するデータの永続性は保証していない。

### 8.2 Windows API

現在はANSI版のWindows APIを使用している。

以下の課題が残る。

- Unicodeファイル名への対応。
- MAX_PATHによるパス長制限。
- 相対パス使用時に作業ディレクトリが変更される場合への対策。

### 8.3 保存処理の統合

共通保存関数のファイル保護機構は実装済みであるが、以下の処理への統合は未実施である。

- リサンプリング済みCSVの保存。
- Record時のCSV保存。
- CLIオプション --overwrite。

### 8.4 実機再生の安全性

CSV形式の検査と実機再生の安全性検査は独立して扱う。

今回の変更によって実機再生を許可することはない。
